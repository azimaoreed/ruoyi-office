# 按需部署指南（只部署部分功能 / 模块）

本文面向 **RuoYi Office（yudao 多模块）** 项目，目标是：**在不部署“全量业务模块”的前提下，只上线你需要的那部分功能**（例如只上线系统管理 + OA，或只上线系统管理 + CRM）。

> 如果你只做“后端单体部署”，优先阅读本文的 **第 2、3 章**；更完整的单体落地步骤可同时参考 `docs/后端部署指南.md`。

---

## 1. 项目形态速览：两种运行方式

该仓库是一个 Maven 多模块工程，既支持：

1. **单体模式（推荐做按需部署）**  
   运行 `yudao-server`：它是一个“容器”应用，通过在 `yudao-server/pom.xml` **引入哪些 `yudao-module-xxx-server` 依赖**来决定启用哪些业务模块。  
   - 优点：部署简单（通常只需要 MySQL + Redis + 一个后端 Jar / 容器）。
   - 缺点：模块越多，Jar 越大；单点扩展能力不如微服务。

2. **微服务模式（按需部署 = 只启动部分服务）**  
   运行 `yudao-gateway` + `system-server`/`infra-server`/`bpm-server` 等多个服务，通过 Nacos 注册发现与配置中心进行组装。  
   - 优点：服务可独立伸缩、故障隔离更好。
   - 缺点：依赖更多（通常需要 Nacos 等），部署复杂度更高。

---

## 2. “按需”到底改哪里：模块开关点

### 2.1 单体模式：改 `yudao-server/pom.xml` 的依赖

`yudao-server` 的定位在 `yudao-server/pom.xml` 已写明：通过引入 `yudao-module-xxx-server` 来提供 API。  
因此 **按需启用/禁用模块** 的最直接方式是：

- 在 `yudao-server/pom.xml` 中 **注释/取消注释**目标模块依赖（仓库里已经给了不少注释示例）。

### 2.2 微服务模式：改“启动哪些服务”+（可选）删网关路由

微服务按需部署时：

- **只启动你需要的服务**即可（例如只启动 `system-server`、`infra-server`、`gateway-server`）。
- 可选：在 `yudao-gateway/src/main/resources/application.yaml` **删除/注释不用的路由**，避免转发到不存在的服务导致 503。

## 3. 单体按需部署（推荐）

> 单体模式运行的是 `yudao-server`（端口默认 48080），并且在 `yudao-server/src/main/resources/application.yaml` 中默认 **禁用 Nacos 注册发现与配置中心**，因此通常只需要准备 **MySQL + Redis** 即可。

### 3.1 选择模块：常用模块与对应依赖

> 单体模式下，下表的 “Maven 依赖（yudao-server 引入）” 是你真正需要关心的开关点。

| 业务模块 | Maven 依赖（`yudao-server` 引入） | 微服务服务名（供对照） |
|---|---|---|
| 系统（必选） | `yudao-module-system-server` | `system-server` |
| 基础设施（必选） | `yudao-module-infra-server` | `infra-server` |
| 工作流 | `yudao-module-bpm-server` | `bpm-server` |
| OA | `yudao-module-oa-server` | `oa-server` |
| HRM | `yudao-module-hrm-server` | `hrm-server` |
| 资产 | `yudao-module-asset-server` | `asset-server` |
| WMS | `yudao-module-wms-server` | `wms-server` |
| 会员 | `yudao-module-member-server` | `member-server` |
| 支付 | `yudao-module-pay-server` | `pay-server` |
| 报表 | `yudao-module-report-server` | `report-server` |
| 公众号 | `yudao-module-mp-server` | `mp-server` |
| CRM | `yudao-module-crm-server` | `crm-server` |
| ERP | `yudao-module-erp-server` | `erp-server` |
| AI | `yudao-module-ai-server` | `ai-server` |
| IoT | `yudao-module-iot-server` | `iot-server` |
| 商城（拆分） | `yudao-module-product-server` / `yudao-module-promotion-server` / `yudao-module-trade-server` / `yudao-module-statistics-server` | `product-server` / `promotion-server` / `trade-server` / `statistics-server` |

### 3.2 修改模块启用集合

编辑 `yudao-server/pom.xml`，保留你需要的依赖，注释掉不需要的依赖，例如：

- **最小可用（系统管理 + 基础设施）**：保留 `system`、`infra`，注释 `bpm/oa/hrm/...`
- **OA + HRM（含流程）**：保留 `system`、`infra`、`bpm`、`oa`、`hrm`

> 提示：如果你希望“完全不编译某些模块”，除了注释依赖外，也可以结合 `mvn -pl` 只构建必要模块（见下一节）。

### 3.3 构建单体 Jar（本地/CI）

在仓库根目录执行（单体推荐 `boot` profile）：

```bash
mvn -Pboot -pl yudao-server -am clean package -DskipTests
```

产物一般在：

- `yudao-server/target/yudao-server.jar`

### 3.4 数据库初始化与“只显示部分功能菜单”

单体部署指南里默认导入的是全量初始化脚本：

- `sql/mysql/ruoyi-vue-pro.sql`
- `sql/mysql/quartz.sql`

这套脚本往往会包含大量菜单、字典等初始化数据。**如果你只部署部分模块**，建议同步做两件事：

1. **后端层面禁用模块**：通过 `yudao-server/pom.xml` 不引入对应模块（核心开关）。
2. **菜单层面隐藏未部署模块**（避免前端点击后 404/500）：  
   在数据库中对 `system_menu`（以及关联的 `system_role_menu`）进行清理/屏蔽。

一个相对安全的做法是“先查后改（软删除优先）”，例如：

```sql
-- 1) 先用 name/path/permission 过滤出候选菜单（按你的实际模块关键字调整）
SELECT id, parent_id, name, path, permission
FROM system_menu
WHERE name LIKE '%OA%' OR path LIKE '%oa%' OR permission LIKE 'oa:%';

-- 2) 软删除菜单（保留数据以便回滚）
UPDATE system_menu SET deleted = b'1' WHERE id IN (/* 上一步查到的 id */);
```

> 不同模块的菜单关键字不完全一致，建议以 `name/path/permission` 三个维度组合过滤；不要盲删全表。

### 3.5 运行方式

**方式 A：直接运行 Jar**

```bash
java -jar yudao-server/target/yudao-server.jar --spring.profiles.active=prod
```

**方式 B：Docker Compose（单体）**

仓库已提供单体编排示例：`yudao-server/docker-compose.yml`（MySQL + Redis + yudao-server）。

如果你选择用 Docker 镜像运行 `yudao-server`，在构建完 Jar 后可执行：

```bash
docker build -t yudao-server:latest ./yudao-server
```

> 更完整的服务器落地步骤（目录、初始化脚本上传、构建镜像等）请参考 `docs/后端部署指南.md`。

## 4. 微服务按需部署（只启动部分服务）

当你选择微服务形态时，“按需”主要体现在 **只启动必要服务**。

### 4.1 最小服务集合（建议）

通常至少需要：

- `system-server`（认证鉴权、菜单权限等）
- `infra-server`（基础能力：文件、任务、日志等，具体看你启用的功能）
- `gateway-server`（统一入口）
- 以及你实际需要的业务服务（如 `bpm-server`、`crm-server`）

另外，微服务一般会用到：

- Nacos（注册中心 + 配置中心）
- MySQL、Redis

### 4.2 构建（示例）

只构建你要跑的服务（示例：gateway + system + infra）：

```bash
mvn -Pcloud -pl yudao-gateway,yudao-module-system/yudao-module-system-server,yudao-module-infra/yudao-module-infra-server -am clean package -DskipTests
```

### 4.3 启动与端口冲突提醒

注意：仓库内部分模块的 `server.port` 可能存在重复（更适合在容器中隔离运行）。如果你要在同一台宿主机直接多进程启动，请：

- 运行时覆盖端口：`--server.port=xxxxx`  
或
- 在各自的 `application.yaml` 中调整为不冲突的端口。

### 4.4 网关路由（可选精简）

网关路由在：

- `yudao-gateway/src/main/resources/application.yaml`

只部署部分服务时，你可以删除/注释不需要的 `routes`，减少无效转发与噪音日志。

---

## 5. 推荐的“部分功能”组合（给决策用）

1. **最小后台**（推荐用于快速上线/试点）  
   - 模块：`system` + `infra`
2. **OA/HR 人事协同**（典型办公场景）  
   - 模块：`system` + `infra` + `bpm` + `oa` + `hrm`
3. **进销存/客户**（业务型）  
   - 模块：`system` + `infra` + `crm` + `erp`（按需加 `bpm` 做审批流）

## 6. 常见问题排查（按需部署最容易踩的坑）

1. **前端菜单还在，但点击接口报错/404**  
   - 原因：菜单数据在数据库中仍然存在，但对应后端模块未部署。  
   - 处理：清理/软删除 `system_menu` 及角色授权；或使用一套“只含必要菜单”的初始化 SQL。

2. **某些功能运行时报缺表**  
   - 原因：未导入相关 SQL（或只导入了部分库表）。  
   - 处理：补齐初始化脚本；按模块补齐对应表结构与字典数据。

3. **微服务启动后网关 503**  
   - 原因：路由指向的服务未启动 / 未注册到 Nacos。  
   - 处理：只保留需要的路由；确认 Nacos 注册、命名空间、服务名一致。

4. **微服务启动时一直尝试连接 MQ / 调度中心等中间件**  
   - 原因：各模块的 `application-*.yaml` 里可能包含 RocketMQ / RabbitMQ / Kafka / XXL-JOB 等示例配置。  
   - 处理：按需关闭或改为你真实可用的地址；不需要的组件尽量显式禁用（例如 `xxl.job.enabled: false`）。
